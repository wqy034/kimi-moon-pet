# 输入气泡：最小版本（2026-10-24）

本节覆盖此前三态、草稿保存和跟随约定。用户手测发现旧输入关闭后仍显示、按钮失效，现按用户确认的最小交互重新实现。以下为实现规则，实际交互仍须用户手测，编译通过不等于已验收。

## 输入与入口

- 双击桌宠：打开或隐藏整个输入组件；右键/托盘「跟她说话」保留为打开入口。
- 只有固定高度输入条（320×42逻辑px）和小圆球（42×42）两种显示形态。无顶部工具栏、发送/关闭/展开按钮、更多菜单、参数和历史列表。
- 圆球位于输入条开头，点击收起/恢复，拖动圆球移动整个组件，拖动松手不触发展开。
- 默认提示「回车发送，Shift+回车换行」。长行横向滚动；换行和多行粘贴只在固定一行高的编辑区域内滚动到光标，不调整窗口高度。文字区保留系统复制/粘贴菜单。
- Enter发送，Shift+Enter插入换行，中文输入法确认候选不发送。保留4000 Unicode字符上限和并发请求拦截，没有发送确认弹窗。
- 请求接收确认后清空仍对应本次提交的输入；用户已经继续编辑时保留新内容。发送失败保留当前框内文字；正在回复时可以继续写，但不并发提交第二次用户请求。
- Esc隐藏组件；双击隐藏、Esc或系统关闭时清空未发送文字。收成圆球只隐藏当前编辑区，本次运行内文字仍在，恢复时继续编辑。无草稿自动保存或重启恢复，启动默认关闭。

## 位置、焦点与原生执行

打开时按人物可见身形水平居中，但垂直位置避开主窗口整块透明画布，上缘空间不足时选择整窗左侧、右侧或下侧，保留12px间距并限制在所在屏幕工作区内。之后自由摆放，不跟随人物，不因拎起/睡姿/缩放/隐藏人物改变输入位置或显隐。收起/恢复保持圆球的左上位置，必要时约束到工作区，输入条向右展开。

用户显式打开/恢复后才请求输入焦点，失焦不隐藏、不清空。最小化不再保留编辑状态；隐藏通过系统移交焦点。输入窗口不允许系统边缘缩放，不做周期性尺寸修正。显隐必须通过Tauri的show/hide配对执行，禁止绕过框架直接调用Win32 ShowWindow；首次显示后核对真实内容区，异常最多补一次set_size并报错，不循环重排。

`input_bubble.rs`只拥有运行时mode、session、焦点和快照。删除草稿保存命令及版本链，`chat_send`只接收正文与聊天数据代次；启动时移除旧版config.input_component_v1遗留项，不改SQLite schema、已发送历史、Key和养成布局。损坏/未知数据库仍沿原有错误处理，不静默清空。

所有输入窗口显隐、尺寸和焦点操作在异步入口执行，原生操作按序串行，圆球切换依据Rust当前形态执行，不依赖前端迟到快照；调用窗口API时不持有输入Service锁。窗口事件回调只用短锁更新状态，不同步等待执行队列。迟到ready不能重新打开已经隐藏的组件。

## 桌宠手势

短按单击延迟到双击判定结束再发原触摸反馈，双击识别成功不再追加两次戳脸。读取系统双击时间（约束200～1000ms）和点击范围，范围按当前DPI换算。长按220ms/移动超过8px仍走原有拎起，并取消等待中的单击。双击的真实观感、睡姿/缩放后的命中、触摸延迟必须手测。

## 设置与回复

桌宠右键/托盘提供「交流设置」「回看交流」，进入现有交流资料窗口。服务商、Key、连接检查、互动开关、停止、重试和清空记录都在设置页；未来完整设置页可接管此入口。输入条只有圆球和文字区，错误以边框及悬停提示呈现，不增加工具栏。

完整回复仍在原生对白窗口流式展示，可以展开、滚动、悬停暂停、收起；停止按钮在回复窗口及设置页。收起回复、隐藏/最小化输入不取消网络，停止、换配置、清空记录才撤销。回复窗口停止操作携带请求ID，旧回复的迟到点击不能停掉新请求。

## 交流期间的统一调度

输入框正在编辑、请求生成中、聊天回复尚在展示/等待临时卡片让位时，统一视为交流时段，仍由BehaviorDirector登记chat活动。期间不参选自主看书、散步、哈欠、主动台词和自动入睡；原有阅读被中断，不从半页恢复。完成后短暂await，剩余阅读回复/输入期间为idle，不持续播放期待动作。

CLI、拎起、下坠、触摸反馈、菜单、投喂、琴盘和打工仍按原优先级执行，网络与打工计时不因输入框显示而停。临时动作结束后若仍在交流，回到chat活动。圆球或闲置未获焦输入条本身不长期占用活动槽。交流结束重设空闲基准，避免立即睡着。

自主台词不能覆盖交流；触摸/生活显式反馈、额度卡片按原规则临时占用对白，尚未过期的最新聊天回复保留并在临时卡片结束后恢复。新流式字符不覆盖正在拖动的卡片；拖动中返回的额度结果等到松手再显示。显式停止或清空可以结束旧回复的拖动并撤下内容。所有内容有owner，隐藏计时器、悬停、拖动和收起操作核对owner；旧事件不能修改新气泡。隐藏过的同请求不因后续流式内容复活；换配置/清空后的旧请求仍由generation过滤。

## 日志与开发检查

`debug.log`新增以下无正文/无Key日志：

- `input-ui action=... id=... stage=click/done/failed/waiting`：前端意图、命令结果和3秒等待提示；脚本错误只记类别。
- `input-native action=... stage=received/begin/done/observed`：原生命令、执行及实际visible/内容区size/outer/无框标志；open/ready/drag失败记录failed。
- `input-ui stage=layout mode=... viewport=... orb=... editor=...`：页面真实视口和控件尺寸，不含文字。
- `conversation active=... editing=... generating=...`：交流状态边界。
- `chat-request id=... generation=... source=... stage=start/complete/failed/cancelled`：请求生命周期，不记录正文、Key或网络错误对象。
- `speech owner=... stage=received streaming=...`：回复归属，与原director日志对应。

仅运行cargo check、Clippy all-targets -D warnings、静态语法/资源审查、进程和日志检查；不模拟键鼠、不自动发送付费请求。

## 用户手测重点

1. 双击打开/隐藏、Esc关闭、圆球收起/恢复/拖动；连续操作无僵死或长扁形。遇问题保留debug.log，对照前端click与原生received/begin/done/observed。
2. 长文本横向滚动、Shift+Enter换行、多行粘贴、输入法候选、连续回车、请求接收后立即继续输入；无二次确认，无草稿落盘。
3. 关闭清空未发文字；最小化恢复当前文字，退出重启不恢复输入框或未发文字；旧已发送聊天历史、Key、养成存档正常。
4. 输入、等待回复、阅读回复时不看书/散步/主动说话/自动睡觉；圆球闲置后恢复原日常节奏。
5. 流式中触摸、投喂、拖动对白、额度查询；回复让位后恢复，旧计时器/悬停/收起不影响新内容，主动收起不复活。
6. 单击触摸判定延迟可接受，双击不戳两次；长按拎起、落地、缩放、屏幕边缘及跨DPI仍正常。明确停止、错误Key、断网、清空后迟到流等API项由用户手测。

## 2026-10-24 系统标题栏与关闭失效定位

用户截图只有系统标题栏；日志中ready后仍visible=true、内容区304×3（外窗320×42），多次hide后仍visible=true。对照本机Tao源码：set_visible通过内部VISIBLE标记决定是否应用样式；从隐藏创建的窗口直接Win32 ShowWindow会绕过此标记，首次show的SWP_FRAMECHANGED/无框布局未执行，后续hide因内部仍为false成为空操作。这是本轮已确认的调用错误，不能归为按钮复杂或单纯被人物盖住。

修正为框架show/hide；show后检查内容区和decorated，hide后检查真实显隐。默认位置额外避开人物原生整窗，防止透明画布吞掉输入。开发检查依旧只代表编译、静态审查及进程状态；真实圆球点击、拖动、Esc和双击隐藏仍由用户手测，用新日志核对结果。

修正版运行后的真实操作日志已出现：ready后内容区/外窗均320×42、无框标志false；圆球点击后内容区/外窗均42×42；hidden命令后visible=false；重新打开恢复320×42。前端对应视口320×42、圆球36×36、输入区263×24。以上来自正常用户操作产生的日志，无模拟键鼠；未据此宣称拖动、跨DPI、API或全部视觉交互已验收。
